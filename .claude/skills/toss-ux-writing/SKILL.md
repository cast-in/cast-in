## 라이팅 코어밸류 (5가지)

토스 라이팅의 정체성. 모든 원칙과 가이드라인은 여기서 출발해.

| 코어밸류 | 의미 |
|---------|------|
| **Clear** 명확한 | 단어의 의미가 어렵거나 모호하지 않게. 메이커가 아닌 사용자가 이해할 수 있는 문장 |
| **Concise** 간결한 | 사용자는 스캔하지 읽지 않음. 꼭 필요한 내용만 필요한 만큼 |
| **Casual** 친근한 | 금융/IT 어려운 용어와 딱딱한 뉘앙스를 쉽고 친절하게. 토스 보이스톤의 핵심 |
| **Respect** 존중하는 | 클릭을 위해 코스트를 숨기거나 혜택을 과장하지 않음. 진실되고 사용자를 존중하는 커뮤니케이션 |
| **Emotional** 공감하는 | 사실 전달을 넘어, 사용자가 느낄 감정에 공감하고 유대감을 만들기 |

## 라이팅 프린시플 8가지

코어밸류를 실제 문장에 녹여내기 위한 원칙. 가이드라인처럼 "이 문장이 맞다/틀리다"를 판단하는 기준은 아니고, 전반적인 방향성을 잡는 역할.

### 1. Predictable hint
다음 화면을 예상할 수 있는 힌트가 있는가?

버튼 문구나 CTA에서 사용자가 누른 뒤 어떤 화면이 나올지 예상할 수 있어야 해. 혜택을 설명하느라 다음 화면 안내를 빠뜨리면 안 됨.
- X `다른 곳에서 후불결제 하기` (→ 설문조사 화면인데 힌트 없음)
- O `내가 쓰는 브랜드 신청하기`

### 2. Weed cutting
의미 없는 단어를 모두 제거했는가?

넣든 빼든 의사 전달에 영향이 없는 단어 = 잡초. 글자 수를 줄이는 게 목적이 아니라, 의미 없는 단어를 없애는 것.
- X `앞으로 매달 자동 이체될 예정이에요`
- O `매달 자동 이체돼요` ('앞으로', '예정' = 잡초)

자주 나오는 잡초 단어: `혹시`, `앞으로`, `~한 상태예요`, `예정이에요`

### 3. Remove empty sentences
의미 없는 문장을 모두 제거했는가?

화면 안의 잡초. 제목에서 충분히 설명했는데 본문에서 똑같은 말을 반복하거나, 공간이 비어보인다는 이유로 의미 없는 문구를 추가하는 것 금지.

### 4. Focus on key message
정말 중요한 메시지만 전달하고 있는가?

메이커는 맥락을 많이 알아서 지나치게 많은 걸 설명하고 싶어 함. 사용자가 이미 아는 정보는 과감히 생략하고, 지금 꼭 확인해야 하는 내용만 전달.

### 5. Easy to speak
이해하기 어려운 용어나 표현을 사용하지 않았는가?

핵심은 Easy to read가 아니라 speak. 눈으로 읽을 때 어색하지 않아도, 소리 내어 읽었을 때 어색하면 고쳐야 해. 한자어, 문어체, 호흡이 긴 문장이 해당. 한 문장엔 하나의 메시지만.

### 6. Suggest over force
특정 행동을 강요하거나 공포감을 주고 있지 않은가?

사용자에게 선택권이 있다는 걸 느끼게 해야 해. 불필요한 공포감으로 원하는 방향으로 유도하지 않기.
- X `이 혜택을 놓치면 손해보시는 거예요`
- O `이 혜택을 받으려면 지금 완료하세요` (뉴트럴한 톤)

### 7. Universal words
모두가 이해할 수 있고 모두에게 무해한가?

연령, 교육 수준, 업계에 따라 이해도가 다른 용어 지양. 유행어, 은어, 밈은 모두가 이해하지 못할 수 있어서 사용 주의.

### 8. Find hidden emotion
단순히 정보를 전달하는 것을 넘어 사용자의 감정에 공감했는가?

정보 뒤에 숨은 감정을 생각해보기. 대출 상환 푸시를 단순 알림이 아니라 "갚느라 고생 많으셨어요!"로 바꾼 것처럼.

## 가이드라인 (구체적 규칙)

### 1. 해요체 — 예외 없이 적용

모든 문구는 해요체로 통일. 상황·맥락 불문.

### 2. 능동적 말하기

수동형 문장은 예외 규칙에서 정의된 경우에만.

| 나쁜 예 | 좋은 예 | 규칙 |
|--------|--------|------|
| 송금이 됐어요 | 송금했어요 | 됐어요 → 했어요 |
| 연결됐어요 | 연결해요 | '~었' 빼기 |
| 사용이 가능해요 | 사용할 수 있어요 | 동사 바꿔쓰기 |

### 3. 긍정적 말하기

부정형은 예외 규칙에서 정의된 경우에만.

| 나쁜 예 | 좋은 예 |
|--------|--------|
| 혜택이 없어요 | 혜택을 받을 수 있어요 |
| 오류가 발생했어요 | 다시 시도해주세요 |
| 이 서비스는 쓸 수 없어요 | 만 19세 이상이면 쓸 수 있어요 |

> 다이얼로그 왼쪽 버튼: 항상 [닫기]. '취소'는 진행 중 작업이 취소된다고 오해할 수 있어서 금지.
> 혜택 대상 안내: 사용자는 스캔하기 때문에 "쓸 수 없어요" → 서비스 전체를 못 쓴다고 오해. 조건을 명시한 긍정형으로.

### 4. 캐주얼한 경어

과도한 경어는 예외 규칙에서 정의된 경우에만.

| 나쁜 예 | 좋은 예 | 규칙 |
|--------|--------|------|
| 확인하시겠어요? | 확인할까요? | 동사에서 '~시' 빼기 |
| 계세요 | 있어요 | '계시다' → '있다' |
| 여쭤볼게요 | 확인할게요 | '여쭤보다' → '확인하다, 묻다' |
| 고객님께 | 고객님에게 | '께' → '에게' |

> 어색한 경우: '~시'를 기계적으로 빼면 어색할 때는 파악하고 싶은 정보를 주어로 문장 재구성.
> 예: "생년월일이 어떻게 되세요?" → "생년월일이 언제예요?"

### 5. '{명사}+{명사}' 쓰지 않기

| 나쁜 예 | 좋은 예 | 규칙 |
|--------|--------|------|
| 계좌 조회 | 계좌를 조회해요 | 한자어 동사형으로 |
| 한도 초과 | 한도가 초과돼서 | '{명사}가 {명사}해서' 형태로 |

## 에러 메시지 원칙

핵심 가치: Navigating — 사용자가 다음 단계로 무엇을 해야 할지 안내하고 있는가.

좋은 에러 메시지에 담겨야 하는 것:
1. 지금 사용자가 어떤 상황에 처했는지 (상황 설명)
2. 왜 이런 상황이 됐는지 (원인)
3. 어떻게 해결할 수 있는지 (해결책)

에러 메시지 작성 전 순서대로 체크:
1. 이 에러가 꼭 있어야 할까? (UX 개선으로 없앨 수 있지 않나?)
2. 적절한 컴포넌트를 쓰고 있나? (토스트는 3~5초 후 사라지므로 긴 내용 금지 → 다이얼로그 사용)
3. 해결책을 명확하게 제시하고 있나?
4. 개발자용 에러 코드가 사용자에게 그대로 노출되지 않나?

## 마케팅 문구 원칙

토스는 클릭을 위해 과장하거나 불안을 자극하지 않음. 모두가 이해할 수 있는 말만 사용.

- 사용자의 상황을 단정하거나 추측하는 표현 지양
- 유행어, 은어 지양
- "마음껏"보다 "1장은 무조건" — 작지만 확실한 혜택이 더 신뢰를 줌
- 심리적 부담을 줄이는 단어 선택: `가입하기` → `준비하기`
- CTA에 혜택 + 행동 두 가지 넣으면 메시지 과부하 → 지금 바로 할 수 있는 행동 하나에만 집중

## 예외 규칙

### 수동형 써도 되는 경우
① 서비스 종료 / 기간 만료 — 주어 강조, '종료'·'만료' 뉘앙스 전달 (단, 주기적으로 반복되는 종료엔 '종료돼요' 쓰지 않음)
② 사용자에게 미치는 영향 — 연체, 해지, 적용 등 인과관계 명확히
③ 사용자 안심 — 정보 수집 안내 등 민감한 상황
④ 표기 통일: `되어요` (X) → `돼요` (O)

### 경어 써도 되는 경우
① 사용자의 맥락을 활용해서 질문할 때 ('시나요?', '셨나요?' 형태)
② 사용자의 상황을 추정할 때 (토스에 명확한 정보가 없을 때)
③ 사용자의 선의가 필요할 때 (설문조사 등)

### 부정형 써도 되는 경우
① 서비스를 정책상 쓸 수 없을 때 (쓸 수 없는 이유 반드시 함께 안내)
② 일부 기능만 쓸 수 없을 때 (명확히 인지시킬 때)
③ 사용자 안심 — 정보 수집 안내 등 민감한 상황

## 문구 작성 체크리스트

### 기본
- [ ] 해요체인가?
- [ ] 능동형인가? (수동형 예외 해당 여부 확인)
- [ ] 긍정형인가? (부정형 예외 해당 여부 확인)
- [ ] 과도한 경어가 없나? (경어 예외 해당 여부 확인)
- [ ] '{명사}+{명사}' 나열 없나?
- [ ] '되어요' 대신 '돼요'를 썼나?
- [ ] 잡초 단어 없나? (혹시, 앞으로, ~한 상태, 예정 등)

### 버튼 / CTA
- [ ] 다음 화면을 예상할 수 있나? (Predictable hint)
- [ ] 다이얼로그 왼쪽 버튼이 있다면 '닫기'로 썼나?
- [ ] 하나의 행동만 담고 있나?

### 에러 메시지
- [ ] 이 에러가 꼭 필요한가?
- [ ] 적절한 컴포넌트를 쓰고 있나?
- [ ] 상황 + 원인 + 해결책이 담겨 있나?
- [ ] 개발자용 에러 코드가 노출되지 않나?

### 8가지 프린시플 점검
- [ ] Predictable hint: 다음 화면 예상 가능한가?
- [ ] Weed cutting: 잡초 단어 없나?
- [ ] Remove empty sentences: 반복/불필요한 문장 없나?
- [ ] Focus on key message: 핵심만 남겼나?
- [ ] Easy to speak: 소리 내어 읽어도 자연스러운가?
- [ ] Suggest over force: 강요/공포감 없나?
- [ ] Universal words: 모두가 이해할 수 있는 단어인가?
- [ ] Find hidden emotion: 사용자 감정에 공감하고 있나?
